# 幸运号码后台表格导入与资料编辑

在 Admin 的幸运号码活动详情页增加「导入号码资料」。管理员上传 Excel 或 CSV 后，系统按表格里的号码关联该活动的号码池。在抽取人列表的「操作」栏加入「编辑资料」，打开后按上传表头生成表单，并预填该号码保存的资料。

**同一活动、同一号码共享一份资料**。例如，活动里的 40 号对应「保温杯」，两人都抽中 40 号时，任一行打开的都是这份资料。在一行里保存后，另一行下次打开会读到新值，再次导出也会采用新值。弹窗明确提示同号共享。

## 与现有抽取的关系

| 现有逻辑                                                                                                                   | 接入方式                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Admin 创建页生成 1 到最大号码的号码池。活动详情页按参与记录分页，列表响应已有参与记录 `id`、`username` 和 `drawn_number`。 | 导入校验实际号码池，行操作使用参与记录 `id`。Admin 类型补上 `id`，Table 改用它作为 `rowKey`。                                  |
| 抽取从号码池随机取一条，记录到参与表。当前逻辑允许不同人抽到同号。                                                         | 用 `activity_id + drawn_number` 定位资料。导入仅补充资料，现有抽取范围、概率、限制、Events 页面和公开接口继续沿用现有行为。    |
| 「取消抽取」软删除参与记录。                                                                                               | 取消后，该记录的资料接口返回 `404`，号码资料仍可供其他同号记录或之后抽中同号的人使用。活动软删除后，后台接口也停止访问其资料。 |

## Admin 操作流程

1. 在活动详情卡片右上角、现有「导出列表」旁点击「导入号码资料」。选择文件和号码列，表头为「号码」或 `drawn_number` 时默认识别。Excel 有多张工作表时显式选择其中一张。
2. 选好文件即可点击「确认导入」。「预览」是可选操作，用于查看动态字段、部分样例和新增、已有差异、无变化的条数。导入失败时显示工作表、行号、列名与原因，并保留文件和选项以便修正后重试。
3. 确认导入后刷新当前分页。参与列表支持「编辑资料」「查看资料」和「资料未导入」三种状态，分别对应可编辑、只读和没有匹配资料的记录。活动开始前可先导入，已有抽取结果的活动也可补导和维护资料。
4. 打开 Ant Design `Modal + Form`，顶部只读显示号码和抽取人。按上传表头顺序生成文本输入项，有换行的现有值使用多行输入框。切换记录时重新取数并重置表单。保存成功后关闭，失败时保留已输入内容。遇到版本冲突时提示重新载入并保留草稿以便核对。
5. 点击现有「导出列表」，下载包含抽取记录和对应号码资料的 CSV。

导入表格示例

```csv
号码,礼品名称,领取位置,备注
40,保温杯,A 区,领取时核对号码
93,咖啡礼盒,B 区,
```

点开抽到 40 号的记录会看到「礼品名称」「领取位置」「备注」三个可编辑字段。「号码」只用于关联，抽取人来自参与记录。

## 导出列表

-   CSV 每条有效抽取记录一行，包含当前活动所有分页的数据。前三列固定为「号码」「抽取人」「抽取时间」，随后按活动保存的资料表头顺序，把每个字段展开成独立一列。导入时选定的号码列用于关联，导出统一使用固定的「号码」列。
-   按 `activity_id + drawn_number` 左关联资料。多人抽到同号时，每人的记录各占一行，后面的资料列填入该号码同一份最新保存值。未匹配到资料的抽取记录保留，资料列留空。活动尚未导入资料时只导出前三列。未被抽中的号码和已取消的记录不产生导出行。
-   动态列与固定列重名时，导出表头加「资料 · 」前缀。若仍重名，追加递增编号直到唯一。表单里的字段名仍使用上传表头。

示例中 40 号有两条抽取记录，两行资料一致。17 号尚未导入资料，仍保留这一行。

```csv
号码,抽取人,抽取时间,礼品名称,领取位置,备注
40,111,2026/11/23 19:02:40,保温杯,A 区,领取时核对号码
93,1,2026/11/23 18:48:26,咖啡礼盒,B 区,
40,示例用户甲,2026/11/23 18:40:00,保温杯,A 区,领取时核对号码
17,示例用户乙,2026/11/23 18:32:00,,,
```

## 导入合同

-   文件支持 `.xlsx` 和逗号分隔的 UTF-8 `.csv`，兼容 BOM、引号内逗号与换行。旧版 `.xls` 请另存为这两种格式之一。首个非空行作表头，全空行跳过。其余行列数必须符合表头，Excel 末尾空单元格按空字符串读取。
-   号码去除首尾空白后按十进制整数解析，在 MySQL `INT` 范围内并且实际存在于当前活动的号码池。文本 `040` 与 `40` 都表示号码 40，同文件出现时报告重复。空号码、小数和号码池之外的值报错。允许只导入部分号码。
-   第一批导入确定该活动的表单字段和顺序。列名去除首尾空白，空表头和重复表头报错。后续导入允许重排列顺序，按列名复用字段 ID。增删或重命名列需要独立的字段迁移，首版会给出表头差异。除号码外，字段值首版保存为普通文本。CSV 不自动转型，Excel 数字、布尔和日期按明确的转换规则保存。电话、券码等需要保留前导零或精度的值，应在 Excel 设为文本。Excel 公式单元格提示先粘贴为值。
-   重复导入默认只新增，已有资料保留后台编辑结果。管理员可在导入弹窗明确选择「更新已有号码」，确认后替换文件中这些号码的字段值，空单元格会清空对应字段。文件未覆盖的号码保持原值。任一校验失败时整批回滚。
-   起步限制建议为单文件 5 MiB、每张导入表 10,000 行、50 个资料列、每格 2,000 字符，并设解压体积、解析时限与并发上限。导入前用接近上限的表格测量解析、批量保存以及同时有用户抽取时的延迟。

## 存储与一致性

**需要新增两张表，现有活动、号码池和参与表无需改列或回填。** MySQL 用固定列保存关联关系，用 JSON 保存活动自定义表头与资料。

| 表                         | 主要字段                                                                                               | 约束                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `lucky_number_data_schema` | `activity_id INT`、`columns_json JSON`、`revision INT`、创建和更新时间                                 | `activity_id` 为主键并引用活动表。所有有效导入和表单修改递增 `revision`，记录活动资料变更。                                  |
| `lucky_number_data_row`    | `activity_id INT`、`drawn_number INT`、`values_json JSON`、`version INT`、`updated_by`、创建和更新时间 | `(activity_id, drawn_number)` 为主键，`activity_id` 引用该活动的资料配置。同活动同号码只能保存一行。每次实际更新递增行版本。 |

例如，表头保存为 `[{"id":"c_1","label":"礼品名称"},{"id":"c_2","label":"领取位置"}]`，资料保存为 `{"c_1":"保温杯","c_2":"A 区"}`。后端生成字段 ID，表头只作为显示文字。由于现有号码池的唯一索引包含可空的 `deleted_at`，资料表使用自身的复合主键保证唯一性，导入时向服务端号码池校验归属。

新表显式设置 `paranoid: false`，访问时通过活动的软删除状态控制可见性。未导入的活动视作 `revision = 0`，首批资料在同一事务创建配置和数据行。修改人取自经验证的 Admin JWT `uid`。

确认导入时，在锁外完成文件解析与基础校验，再在事务中锁定活动、按当前资料配置校验表头和有效号码、批量写入资料并更新版本。锁顺序沿用现有抽取先锁活动的约定。保存表单时，按活动和参与记录 ID 查找并锁定仍有效的参与记录，由服务端取出 `drawn_number`。按 `version` 更新资料，过期返回 `409`。更新已有号码时以导入事务读到的当前资料为准。取消抽取后，旧链接无法编辑已取消参与记录的资料。

## API 与权限

路由放在 `/v1/admin/lucky-number` 下。沿用活动权限体系，读资料校验 `WATCH_EVENT`，上传和保存校验 `EDIT_EVENT`。Admin 根据权限展示操作，服务端独立校验。新增资料接口发送 `Cache-Control: no-store`。

| 请求                                       | 约定                                                                                                                                                        |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /:key/number-data/import/preview`    | multipart 上传文件、工作表、号码列和导入模式。多工作表尚未选定时先返回表名。预览返回有界的样例、计数和校验错误，不写业务数据。                              |
| `POST /:key/number-data/import/commit`     | multipart 直接上传文件、工作表、号码列和导入模式。服务端在校验后提交。缺少工作表或号码列选择时返回 `422` 与可选值，前端保留文件供重试。                     |
| `GET /:key/participations/:id/number-data` | 校验活动和参与记录归属，返回号码、抽取人、字段定义、字段值及行 `version`。无匹配资料时返回明确错误。                                                        |
| `PUT /:key/participations/:id/number-data` | 提交 `{ "version": 3, "values": { "c_1": "保温杯", "c_2": "A 区" } }`。只接受当前表头声明的字段 ID 与长度合规的文本，返回最新版本。客户端无需提交目标号码。 |
| `GET /:key/participations/export`          | 校验 `WATCH_EVENT` 并生成当前活动完整的 CSV。以参与记录为主表，按现有列表顺序输出，批量关联资料，返回带 UTF-8 BOM 的 `text/csv`。                           |

分页列表按当前活动和本页号码批量查询是否有资料。详情页请求可带 `include_number_data_status=1`，只增加 `has_number_data`，弹窗打开后再查表单值。公开接口继续沿用原字段。

Admin 在点击「导出列表」时使用现有鉴权客户端请求文件并下载，移除切换分页时为导出预取全量记录的请求。服务端在一次导出中读取一致的参与记录与资料快照，使用普通读查询。CSV 正确转义逗号、引号和换行，对来自用户输入的表头及单元格做公式防护。没有有效记录时沿用「没有数据可导出」提示。

文件超限返回 `413`，格式或内容有误返回 `422` 并提供可定位的校验项，表单编辑遇到版本冲突返回 `409`。没有权限时沿用现有 `401`、`403` 行为。

服务端可选 `ExcelJS` 读取 XLSX、`csv-parse` 解析 CSV。当前 Koa 全局已开启 multipart，实施时应让新增导入路由在校验权限后再按专属限额解析上传，并统一清理临时文件。预览不持久化原始文件，导入后只保存字段和文本值。日志只记录管理员 ID、活动、行数、结果和冲突信息，避免 SQL 打印完整数据，错误信息不回显原始单元格值。表单按纯文本渲染。 [ExcelJS 项目文档](https://github.com/exceljs/exceljs) · [CSV Parse 选项](https://csv.js.org/parse/options/)

## 实施与验收

1. 先准备新增表的增量迁移和 Sequelize Model、DAO。部署先执行新增表迁移，再部署 API 与 Admin。原有活动默认没有资料。回退应用代码时保留新增表，避免丢失已导入和编辑的数据。现有 `CREATE_TABLE` 会触发 `sync({ force: true })`，线上迁移须使用单独的非破坏性脚本。
2. 接入解析、预览、确认、读表单和版本校验。用 XLSX 与 CSV 样例验证中文、前导零、空值、引号和换行。覆盖直接导入、预览后导入、缺少选项、错误行、重复号码、跨活动号码、公式、超限、空表、重复导入和整批回滚。
3. 接入详情页导入弹窗及行操作。验收旧活动补导后原有记录即时可编辑、同号多人共享资料、不同活动的同号相互隔离、取消后旧链接不可写、覆盖导入会令已打开的旧表单返回冲突。验证只读用户与无权限用户，以及公开抽取结果。
4. 接入 CSV 导出。验证跨页记录、固定列与动态列顺序、同号重复行、资料留空、旧活动三列导出和取消记录排除。保存一次资料后立即导出，核对所有同号行采用新值。再验证重名表头、文本转义和导出权限。
